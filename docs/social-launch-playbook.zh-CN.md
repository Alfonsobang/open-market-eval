# A 股研究 Agent 实验场：社媒启动策略

## 目标用户

### 1. 研究基础不完整的 A 股研究者

他们会读公告、看财务数据、使用行情软件，但容易在信息时点、数据口径、股票池和回测成交规则上犯错。核心需求不是“再来一个荐股 Agent”，而是获得一套可以检查自己研究过程的公开标准。

### 2. 对 AI 投资有兴趣的实践者

他们能调用模型、搭建工作流或使用量化框架，但不知道怎样证明 Agent 的答案不是搜索摘要拼接、未来信息泄漏或样本内调参。核心需求是用同一任务合同比较不同模型和 Agent。

## 定位

> 不评测 AI 会不会讲股票故事，评测它能否完成可核验的 A 股研究工作。

首发阶段只传播三个具体价值：

1. 五种真实任务：公告搜索、时点查数、事件预测、回测审计、研究备忘录。
2. 八项回测防泄漏自检：用户打开页面即可使用。
3. 公开任务合同：任何模型或 Agent 都能在同一输入、交付物和指标下接受评测。

## 渠道策略

| 渠道 | 用户 | 内容角度 | CTA |
| --- | --- | --- | --- |
| 知乎 / 公众号 | 研究者、数据从业者 | 为什么多数 AI 炒股 Demo 无法验证 | 使用防泄漏清单 |
| 雪球 | A 股研究者 | 一条收益曲线至少需要通过哪八项审计 | 提交一个常见回测错误 |
| 即刻 | AI 产品与开发者 | 把 A 股投研拆成五个 Agent benchmark | 认领一个任务 |
| X / GitHub | 全球 Agent eval 社区 | Point-in-time financial agent evaluation | 接入一个 Agent adapter |
| B 站（第二阶段） | 想看实际效果的用户 | 同一公告任务对比三个 Agent 的全过程 | 复现实验 |

不在首发阶段主攻“小红书荐股流量”或短期行情热点，因为这会吸引错误用户，并迫使项目输出无法验证的即时观点。

## 28 天内容节奏

### 第 1 周：定义问题

- D1：发布《别再问 AI 明天买什么，先看它能不能查对一份公告》。
- D2：发布八项回测防泄漏自检，邀请用户晒出自己未通过的项目。
- D4：用一个公开财务字段示例讲清“期间、单位、口径、版本”四类错误。
- D6：公开征集首批 10 个任务，不征集股票推荐。

### 第 2 周：展示实验

- 发布第一个公告搜索任务的数据卡和 verifier。
- 同一任务跑至少两个公开 Agent，完整展示失败轨迹。
- 做一次“错误答案为什么听起来更像真的”复盘。

### 第 3 周：连接生态

- 发布 Harbor 任务适配过程。
- 发布 AKShare/Qlib 数据接入与时点安全边界说明。
- 向相关开源项目提交一个小而明确的上游改进，不做泛泛宣传 PR。

### 第 4 周：形成连续栏目

- 发布月度 Agent 研究能力表，明确任务数和置信区间。
- 发布最有价值的三个失败案例。
- 公布下一批任务和仍然缺失的数据资产。

## 内容模板

每次发布都使用同一结构：

1. 一个具体失败问题。
2. 一个可复现任务。
3. 一个程序化或独立复核的评分方法。
4. 一个诚实结果，包括失败。
5. 一个低门槛 CTA：运行、认领任务或提交错误案例。

## 运营指标

星标是结果指标，不是首要行动指标。每周记录：

- GitHub 独立访客、克隆数和 README 到 Pages 的点击。
- 防泄漏清单使用次数（后续接入隐私友好的匿名事件统计）。
- 任务 issue 的有效回复数。
- 外部提交的任务、adapter 和复现实验数。
- 首次访问到完成一次 CLI 命令的转化。
- Star、Fork 和 Watch 作为二级指标。

禁止购买 Star、互赞、群发私信、借热点荐股或伪造模型收益。

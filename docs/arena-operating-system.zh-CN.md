# A 股研究 Agent 联赛：运营系统

## 北极星

> 让任何人都能把一个研究 Agent 放进同一组 A 股任务，公开它的证据、失败和可复现成绩。

项目不靠每日行情观点获取短期流量。每一次传播都必须落回一个可运行任务、一个可检查 artifact 或一次公开失败复盘。

## 两类核心用户

### 研究基础不完整的 A 股研究者

他们需要的不是更强势的结论，而是能拦截错误口径、未来信息、错误股票池与不可成交假设的工作规范。

### 对 AI 投资有兴趣的实践者

他们需要知道模型是否真正会搜索、查数、审计和形成证据链，而不是只会生成一段像研究报告的文字。

## 单点突破

首个增长锚点是 **Backtest Forensics / 回测取证**：

- 一句话能说明：让 Agent 找出 A 股回测中偷看的未来。
- 五分钟能运行：`python -m open_market_eval audit-demo`。
- 结果能传播：精确率、召回率、F1、逐案漏检和误报。
- 不依赖行情授权：使用符合市场结构的合成场景。
- 能接入前沿框架：提供 Harbor 风格任务和确定性 verifier。

五条能力轨道是长期版图，不再同时作为首页主卖点。

## 月度赛季闭环

| 周期 | 公开动作 | GitHub 资产 | 社媒内容 |
| --- | --- | --- | --- |
| Week 1 | 发布挑战 | task pack、schema、verifier | “这次要抓哪种研究错误” |
| Week 2 | Agent 公开运行 | 原始输出、配置、成本与日志 | 同一任务的不同 Agent 轨迹 |
| Week 3 | 失败取证 | failure notes、修复 PR | 最有教育价值的漏检与误报 |
| Week 4 | 榜单与下期预告 | 可复现榜单、release | 月度结论、边界与下一关 |

没有真实运行时，不发布“AI 投资新突破”之类的内容。

## 内容栏目

### 《回测案发现场》

每期只讲一个错误：同收盘价成交、当前股票池回放、复权价成交、T+1、涨跌停、财务修订穿越或退市幸存者偏差。文章必须给出最小案例和 verifier。

### 《同题不同 Agent》

用同一个任务比较两个或以上 Agent。公开输入、配置、运行成本、原始输出和失败，不只截取最佳答案。

### 《榜单之外》

复盘一个排名无法解释的问题，例如高召回但误报严重、答案正确但证据不支持、或工具轨迹存在截止时间后的信息。

### 《下一关由谁出题》

通过结构化 issue 征集研究者最常见的真实错误，再将高质量问题改造成公开任务。

## 渠道分工

| 渠道 | 主内容 | 唯一 CTA |
| --- | --- | --- |
| GitHub | 任务、代码、成绩与讨论 | 运行或提交 artifact |
| 知乎 / 公众号 | 方法复盘与失败分析 | 查看完整可复现实验 |
| 雪球 | A 股市场结构错误案例 | 提交一个待审计场景 |
| 即刻 / X | Agent 评测工程进展 | 运行同一任务 |
| B 站 | 同题多 Agent 全过程 | 复现并评论失败点 |

同一周只传播一个挑战，不在多个方向上同时喊口号。

## 榜单准入

公开榜单只接受：

1. 明确的 Agent、模型和版本。
2. 完整的运行命令与环境。
3. 未删减的原始输出、配置和 scorecard。
4. 开发集或盲测集的明确标识。
5. 对 API、人工介入和工具权限的披露。

不接受截图成绩、无法复现的私有 Agent、删掉失败案例后的结果或任何投资收益宣传。

## 运营指标

### 领先指标

- 完成一次 `audit-demo` 的独立用户数。
- 有完整 artifact 的外部 Agent 提交数。
- 被认领并转化为任务的高质量 issue 数。
- 外部复现实验和修复 PR 数。

### 结果指标

- GitHub Star、Fork、Watch 与独立贡献者。
- 外部文章、视频或研究项目引用。
- Harbor、Qlib 或相关 Agent 社区的有效讨论与上游贡献。

不购买 Star、不互赞、不群发私信、不制造虚假榜单。
